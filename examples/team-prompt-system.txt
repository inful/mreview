We are the AcmeCorp platform team.

Project conventions:
- Errors wrap with %w and a short verb-prefix ("read x: %w").
- Tables drive tests when possible.
- Public APIs have godoc; internal helpers don't need it.
- No new third-party dependencies without an ADR in docs/adrs/.

Dependency preferences:
- HTTP → stdlib net/http (not gin, not echo).
- Postgres → jackc/pgx (not database/sql, not gorm).
- JSON → encoding/json (not gjson, not json-iterator).
- Logging → log/slog (not zap, not logrus).

Severity semantics we use:
- "error"   → must block merge. Security holes, data loss, broken
              contracts.
- "warning" → should fix before merge but won't block. Naming, minor
              perf, missing tests for new code paths.
- "info"    → nit. Suggestion-only; the human can ignore.

Documentation standards:
- Every exported package has a doc.go with a one-paragraph overview.
- Every exported function/type in an internal package has at least
  one sentence of godoc describing intent (not mechanics).
- Comments explain WHY, not WHAT.
